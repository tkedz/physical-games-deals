# Extraction model: evaluation on the labelled set

The evaluation record for `physical-deals-from-real-posts` (roadmap `S-01`), Phase 1. It answers the roadmap's S-01 unknown, "which model does the extraction and at what cost per post", and fixes `MODELS` in `scripts/extract/config.mts`.

## Runs

- **Dates:** 2026-09-29, both run by Tomasz with `npm run extract:eval`:
  - prompt version 1 at 13:04 UTC;
  - prompt version 2 at 13:30 UTC.
- **Candidates:** `mistralai/mistral-small-3.2-24b-instruct` and `openai/gpt-4.1-nano`, each called on its own (`models: [id]`, no fallback), one request at a time per model. `qwen/qwen3.8-27b:free` was dropped by Tomasz before any call, because credits had to be bought anyway (`change.md`).
- **Request:**
  - `response_format` in strict `json_schema` mode, generated by zod;
  - `provider.require_parameters: true`;
  - `max_tokens: 4096` and `temperature: 0`;
  - no `reasoning` and no `seed`.
- **Secrets:** the reports contain neither the key nor a request URL. The v1 report was checked by search before it was read. The v2 report was written by the script itself, which prints no request.
- **Reports:** both stay local and gitignored, because they quote the posts:
  - `scripts/extract/eval/eval-report.md` (v1, pasted from the terminal);
  - `scripts/extract/eval/report-v2.md` (v2, written by the script).

### Labelled set

- **Posts:** 55 links from `public.collected_posts`, exported with the query at the end of this record and saved to the gitignored `scripts/extract/eval/posts.json`. By aggregator: pepper 27, lowcygier 16, cenograj 12. Nine of the links were seen in more than one feed.
- **Composition:** 45 links picked at random within their aggregator (20 pepper, 15 lowcygier, 10 cenograj). Up to two per trap pattern added 10 more. In the finished set the patterns match:
  - "do pizzy" (1 post);
  - Game Pass (3);
  - eShop (3);
  - "Przewaga cenowa" (2);
  - key shops (3).

  The sixth pattern, digests with at least four prices, was not counted separately.
- **Labels:** drafted by the agent from the posts as the model sees them, and accepted by Tomasz on 2026-09-29 (`scripts/extract/eval/labels.json`). There are 55 expected items:
  - 23 physical deals that should be listed;
  - 21 digital items;
  - 10 products that are not games;
  - 6 posts that offer nothing to buy.
- **Scoring** (`scripts/extract/evaluation.mts`):
  - Every reply goes through the pipeline's own `toDealRows`, so what is scored is what would reach the page.
  - Items pair by normalised English title, then by platform and price.
  - Each returned item is marked:
    - `listed` or `rejected` as it should be;
    - `leak`, when it is listed but the label says it is not a physical game;
    - `missed`, when it is not listed but the label expects it listed;
    - `wrong game`, when it is listed and matches nothing in the label;
    - `extra offer`, when it is another shop's or platform's offer of a labelled physical game, which is not an error.

## Rule

> Only a model with zero digital leaks is eligible — and only when it answered at all, every post was measured and every reply came from the model asked. Then the fewest missed physical deals wins, then the fewest field errors (price, currency, platform, discount, expiry), then the lowest cost.

The rule is the plan's (Phase 1, change 10). The eligibility conditions after the dash make sure a zero is a measurement.

### What version 2 changed

Version 2 added four rules, each aimed at an error in the v1 report:

- `englishTitle` keeps the words that tell a game from its series, copies the post's title when unsure, and never names another game;
- a collector's edition with the game inside is `game`;
- a digital store or key shop makes an offer digital, whatever its edition is called;
- in cenograj's template only "Rabat" is a discount, never "Przewaga cenowa".

The effect on each model:

- **Mistral Small 3.2:**
  - Discount errors went from 1 to 0: #3 Slaycation Paradise no longer reads "Przewaga cenowa: 30%" as -30%.
  - #21 now carries "Elden Ring Nightreign" instead of "Elden Ring Collector's Edition".
  - No count went up.
- **GPT-4.1 nano:**
  - Leaks went from 3 to 1. #38 is still there: The Witcher 3 on Steam reads as a box on the strength of "Edycja Gry Roku", the very case the new rule names.
  - It still reads "Przewaga cenowa" as a discount.
  - It took #22's release date for an expiry date.

## Verdict

- **Models:** `MODELS = ["mistralai/mistral-small-3.2-24b-instruct"]`, with prompt version 2, and prompt version 3 from 2026-10-06 (above).
  - Mistral Small 3.2 is the only candidate with zero digital leaks in both runs.
  - GPT-4.1 nano leaked in both, so under the rule it is not eligible as a fallback either: a fallback writes deals too.
- **Cost per post:** $0.00020 (v2: $0.0111 for 55 posts; 2,163 input and 166 output tokens per post on average). That comes to:
  - about $0.32 for the 1,573-link backlog;
  - about $0.55 a month at the measured inflow of roughly 2,700 links (research.md, Volume).

## What the first live call settled

- **The request shape is accepted.** Both endpoints took the schema exactly as zod generates it, the `$schema` key and the `.int()` bounds of ±2^53 included, together with `require_parameters`, `max_tokens` and `temperature`. The evidence is 110 valid replies per model over the two runs, with no 400. `toResponseFormat()` therefore keeps the schema as generated.
- **Reasoning stayed off.** Reasoning tokens were zero on both paid models in both runs.

## Findings

- **The one missed physical deal:** #49, No More Heroes 3 at Empik (85.59 zł) and Neonet (89 zł), came back `unclear` in both runs. That happened although the post names two boxed-game retailers and their delivery costs. The miss falls on the safe side of the guardrail.
- **The one platform error:** #25, the collector's edition of Tomb Raider: Legacy of Atlantis, came back as `pc`. The excerpt lists PC, PS5 and Xbox Series X for the game and none for the edition.
- **`englishTitle` can name another game.** #6 Pokémon Pokopia came back as "Pokémon Scarlet" in both runs, v2's rule notwithstanding. The page shows `title`, which is right ("Pokémon Pokopia"). Most of the other seven "title differs" cases are edition words the model kept ("Blasphemous Martyrs' Edition", "Steep X: Gold Edition") or products that are not games.
- **Multi-offer posts come back as intended.** In both runs Mistral returned a second platform (#22 Hellraiser on Xbox Series) and a second shop (#43 Final Fantasy X/X-2 on Allegro), both marked `extra offer`.
- **Shop links:** a shop URL survived only when it was one of the post's own links and not on the aggregator. That happened in pepper posts only (8 kept in v1, 9 in v2) and in no cenograj or lowcygier post, which matches research.md's measurement.

## Not measured

- **Expiry.** No labelled post states when its offer ends, so `expiresOn` and `expiresAt` were not tested; the zero in that column measures nothing.
- **The full mix.** 55 posts are a check on the traps, not an estimate of the error share on the real inflow. That is `review.md`'s job in Phase 3, on 100 random links, and it answers PRD question 3.

## Handoff

### Phase 3 (this change)

- **No fallback model.** A withdrawn or renamed Mistral id answers 404 (`no_endpoint`), which is systemic, so every run turns red until `MODELS` changes. Nothing silently stops.
  - Mistral Small 3.2 carries no `expiration_date` in the catalogue of 2026-09-29, and OpenRouter serves it from four providers behind the one id.
  - A fallback can be added later by putting a candidate into `CANDIDATES` and passing this set.
- **Throughput.** With v2's latency (p50 5.6 s, p90 8.4 s) and `CONCURRENCY` 4, a run clears about 0.7 links a second, or about 340 links in the 8-minute `RUN_BUDGET_MS`. The budget binds before `RUN_LINK_CAP` (400), and the backlog drains in about five scheduled runs.

### S-04 (`deals-matched-to-watchlist`)

- **Don't trust `english_title` alone.** It can name a different game for a title the model does not know (Pokopia → Scarlet). Matching should also consider `title` and `alternative_titles`, or resolve through the catalogue.
- **Edition words stay in some titles** ("Martyrs' Edition", "Royal Edition") despite the instruction, so a name match has to tolerate them.

## Sample query

Read-only, run by Tomasz in the Supabase SQL editor on 2026-09-29. It returns one `posts` cell; the editor's JSON export wraps it in a result row, which `parsePosts` accepts too.

```sql
-- Labelled-set sample for scripts/extract/eval/posts.json. Read-only.
-- One element per link: the representative row (its earliest sighting) and
-- the feed id and platform hint of every row sharing the link.
with links as (
  select distinct on (link) *
  from public.collected_posts
  where link is not null
  order by link, first_seen_at, id
),
tagged as (
  select l.*,
         split_part(l.source, '-', 1) as aggregator,
         coalesce(l.title, '') || ' ' || coalesce(l.content, '') as haystack
  from links l
),
random_pick as (
  select id
  from (
    select id, aggregator,
           row_number() over (partition by aggregator order by random()) as n
    from tagged
  ) ranked
  where (aggregator = 'pepper' and n <= 20)
     or (aggregator = 'lowcygier' and n <= 15)
     or (aggregator = 'cenograj' and n <= 10)
),
trap_pick as (
  (select id from tagged where haystack ilike '%do pizzy%' order by random() limit 2)
  union
  (select id from tagged where haystack ilike '%game pass%' order by random() limit 2)
  union
  (select id from tagged where haystack ilike '%eshop%' order by random() limit 2)
  union
  (select id from tagged where haystack ilike '%przewaga cenowa%' order by random() limit 2)
  union
  (select id from tagged
   where haystack ~* '(eneba|kinguin|g2a|instant ?gaming|cdkeys|gamivo|k4g)'
   order by random() limit 2)
  union
  -- a digest: at least four prices in one post (cenograj's template has fewer)
  (select id from tagged
   where aggregator <> 'cenograj'
     and (length(haystack) - length(replace(haystack, 'zł', ''))) / 2 >= 4
   order by random() limit 2)
)
select json_agg(
         json_build_object(
           'post', to_jsonb(t) - 'processed_at' - 'aggregator' - 'haystack',
           'feeds', (
             select json_agg(json_build_object('source', c.source,
                                               'platform_hint', c.platform_hint)
                             order by c.source)
             from public.collected_posts c
             where c.link = t.link
           )
         )
         order by t.aggregator, t.id
       ) as posts
from tagged t
where t.id in (select id from random_pick union select id from trap_pick);
```
